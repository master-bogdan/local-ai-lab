# local-ai-lab 🧠
Local AI stack with Ollama, Open WebUI, ComfyUI, and monitoring (Prometheus, Grafana, cAdvisor). This project provides a small local stack designed for development, prototyping, and experimenting with local LLM systems and AI web UIs. It is intended to run on Linux and macOS using Docker and Docker Compose.

---

## What's included

- Ollama (LLM runtime / model host)
- Open WebUI (two instances: Core and App Builder)
- ComfyUI (image generation / UI)
- Prometheus + Grafana for monitoring
- cAdvisor for container metrics
- Utility scripts (install, start, clear) and a `Makefile` front-end

This repo aims to be a collection of locally runnable AI developer tools that are easy to configure and manage with Docker Compose.

---

## Prerequisites

- Docker with the Docker Compose plugin (using `docker compose`)
- Optional: GPU and drivers
  - Linux (NVIDIA): install `nvidia-container-toolkit` so containers can use the GPU
  - macOS: GPU support is limited (Apple silicon will run GPU-optimized containers differently; the stack works CPU-only)

## Quick start

Option A — recommended (Make):

```bash
make install  # generate .env, create monitoring files, pull images and Ollama models
make start    # run the stack in foreground
# Use `make clear` to stop the stack and remove generated volumes and files
```

Option B — scripts:

```bash
./scripts/install.sh
./scripts/start.sh     # runs `docker compose up` (foreground)
./scripts/clear.sh
```

Option C — Docker Compose (alternate):

```bash
docker compose up -d
docker compose down -v
```

## Default URLs (host ports)
The `config/*.env` variables get combined into a single `.env` file by the install script. Default ports are taken from the `config/*.env.example` files.

- Open WebUI (core):  http://localhost:3000
- Open WebUI (app builder): http://localhost:3001
- Ollama API:         http://localhost:11434
- ComfyUI:            http://localhost:8188
- Grafana:            http://localhost:3002  (default: admin/admin; change it!)
- Prometheus:         http://localhost:9090
- cAdvisor:           http://localhost:8080

If you change ports in `config/*.env` or from the environment, these URLs will change accordingly.

## Configuration

All runtime configuration is stored under `config/*.env` files. Example files are provided with `.example` suffix. The `scripts/install.sh` will:

- Copy `config/*.env.example` to `config/*.env` if `*.env` files are not found
- Merge `config/*.env` files into the root `.env` file (deterministic merge; last value wins)

Important variables (see examples in `config/*.env.example`):

- `OLLAMA_PORT`: Ollama HTTP API port (default 11434)
- `OPENWEBUI_CORE_PORT`, `OPENWEBUI_APPBUILDER_PORT`: Open WebUI ports (default 3000/3001)
- `COMFYUI_PORT`: ComfyUI UI port (default 8188)
- `PROMETHEUS_PORT`, `GRAFANA_PORT`, `CADVISOR_PORT`: monitoring ports
- `GRAFANA_ADMIN_PASSWORD`, `GF_SECURITY_ADMIN_PASSWORD`: update it after first run
- GPU variables: `OLLAMA_GPUS`, `COMFYUI_GPUS` — set to `all` to use available GPUs or leave unset for CPU-only

The merge logic is implemented in `scripts/install.sh` and keeps the order deterministic (alphabetic by filename). Values from later files override earlier ones.

### Generated files and metadata

- `.env` — generated by `scripts/install.sh` from `config/*.env`.
- `.installed` — sentinel file created by the install script to indicate that installation is complete. `./scripts/start.sh` checks for this file and will run the install step if it’s missing.
- `monitoring/prometheus/prometheus.yml` and `monitoring/grafana/provisioning/datasources/datasource.yml` — generated if missing during install.

Note: `.env` and `.installed` are in `.gitignore` so they won't be committed by default; they are runtime artifacts.

## Installing models

By default `scripts/install.sh` contains a `MODELS` array and will pull a set of models into Ollama when you run `make install` or `./scripts/install.sh`.
There are two model pulling helpers in this repository:

- `scripts/install.sh` — will pull a default model set during the installation workflow.
- `scripts/models-install.sh` — is a separate script that pulls a curated set (or any list of models you specify). Use it to add models after install without running the whole install flow.

To customize it, edit the `MODELS` array inside `scripts/install.sh` with the model names you want.

The script pulls models using `docker compose run --rm ollama` and runs `ollama serve` in the container temporarily while pulling.

### Model management scripts (new)

This repo includes small helper scripts for managing models in Ollama:

- `./scripts/models-install.sh` — Pull one or more models into the Ollama runtime.
  - Usage:
    - Pull the built-in default model set: `./scripts/models-install.sh`
    - Pull specific models: `./scripts/models-install.sh qwen2.5:14b llama3.1:8b`
  - Defaults: If you don't pass any arguments, a curated default set (see script header) will be pulled.

- `./scripts/models-remove.sh` — Remove one or more models from the Ollama runtime.
  - Usage:
    - Remove specific models: `./scripts/models-remove.sh qwen2.5:14b`
    - Remove ALL models: `./scripts/models-remove.sh --all` (interactive; requires typing `YES`)

These scripts use `docker compose run --rm ollama` to run Ollama commands that pull or remove models and will operate against the container volume where Ollama stores model data.

## Development & Operations

- View logs:

```bash
docker compose logs -f
```

- Stop the stack and remove volumes (clear all):

```bash
make clear
# or
./scripts/clear.sh
```

- Restart single service:

```bash
docker compose restart openwebui-core

### Service and GPU notes

- `docker-compose.yaml` currently includes `gpus: all` for Ollama and ComfyUI. If you need CPU-only execution, remove these `gpus` keys or edit the Compose file accordingly; depending on your environment, Docker may ignore `gpus` if hardware is not present.
- The `OLLAMA_GPUS` and `COMFYUI_GPUS` env variables provide a way to indicate GPU preference in the configuration files, but the Compose `gpus` setting is what triggers container access to GPUs in Docker.
```

## Monitoring

Prometheus scrapes cAdvisor and itself by default. A simple Grafana provisioning file is created during `scripts/install.sh` that includes a Prometheus datasource.

Grafana is pre-configured using `monitoring/grafana/provisioning/datasources/datasource.yml` (auto-generated).

## Security & best practices

- Do not expose admin interfaces (Grafana, Open WebUI) to the public Internet unless you secure them with HTTPS and strong authentication.
- Change default passwords (Grafana default admin: `admin`) immediately.
- If running on a machine with multiple users, consider using a non-root container runtime and a reverse proxy with authentication.

## Troubleshooting

- If install failed with model pull errors, check `docker compose run --rm --entrypoint sh ollama` logs, your network, and Ollama runtime compatibility with your GPU.
- To list currently installed models in Ollama:

```bash
docker compose run --rm ollama list
```
- Check container logs: `docker compose logs <service>` or `docker compose logs -f` for live logs.
- If you modified `config/*.env` and the `.env` does not get updated, run `./scripts/install.sh` again to regenerate.

---

## Advanced topics

- Running on GPU: ensure `nvidia-container-toolkit` is installed and the `gpus: all` setting is supported by your Docker engine.
- To make changes permanent, edit `config/*.env` files and re-run `make start` or `./scripts/start.sh`.
